# 参考项目、论文与使用边界

本文件说明上游来源、版本锁、用途和本项目不声称的部分。源码不随仓库分发；`external/` 由 `references.lock.yaml` 固定 commit 获取。

## 1. 上游项目

| 项目 | 用途 | 本项目改造 | 不声称 |
|---|---|---|---|
| [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness) | GSM8K/MMLU-Pro/BBH/IFEval 的参考实现与逐样本核对 | 接入任务、原生指标、样本级记录、污染/稳健性 | 不自称通用评测框架，不改上游题目 |
| [LlamaFactory](https://github.com/hiyouga/LlamaFactory) | 四卡 LoRA SFT 执行 | 生成 messages 数据、YAML、dataset_info、权重接回 | 不把训练框架当自研，不在本地跑 Jupyter |
| [EvalPlus](https://github.com/evalplus/evalplus) | HumanEval+ 功能测试 | 接入 pass@1、受限容器执行 | 不改测试用例，不把执行失败算 pass |
| [RULER](https://github.com/NVIDIA/RULER) | 长上下文任务定义参考 | 4K/8K/16K 固定种子本地诊断生成器 | 不称官方 RULER 榜单提交 |
| [Qwen3-8B-Base](https://huggingface.co/Qwen/Qwen3-8B-Base) | 主被测基座 | 固定 revision、completion/chat 协议适配 | 不训练基座，不做预训练研究 |
| [Qwen3-4B-Base](https://huggingface.co/Qwen/Qwen3-4B-Base) | 主要结论复核 | 同协议小模型复核 | 不与 8B 结果混池 |

## 3. 方法与论文

| 主题 | 参考 | 在本项目中的位置 |
|---|---|---|
| GSM8K 数学推理 | Cobbe et al., *Training Verifiers to Solve Math Word Problems* | 主任务与最终答案提取 |
| SVAMP 数学泛化 | Patel et al., *Are NLP Models really able to Solve Simple Math Word Problems?* | 迁移检验 |
| MMLU-Pro | Wang et al., *MMLU-Pro: A More Robust and Challenging Multi-Task Language Understanding Benchmark* | 知识与推理辅助指标 |
| BBH | Suzgun et al., *Challenging BIG-Bench Tasks and Whether Chain-of-Thought Can Solve Them* | 23 子任务 exact match |
| IFEval | Zhou et al., *Instruction-Following Evaluation for Large Language Models* | 规则验证；unsupported 不算 pass |
| HumanEval / EvalPlus | Chen et al.; Liu et al., *Is Your Code Generated by ChatGPT Really Correct?* | 功能正确性 |
| RULER | Hsieh et al., *RULER: What's the Real Context Size of Your Long-Context Language Models?* | 长上下文诊断设计 |
| LoRA | Hu et al., *LoRA: Low-Rank Adaptation of Large Language Models* | 训练适配 |
| 数据选择/难例优先 | 已有 curriculum/data-selection 研究 | 本项目只做等预算对照，不声称首次提出 |

论文支持的是方法背景，不是本项目的实验结果。没有真实运行前，不引用论文效果替代自己的测量。

## 4. 与零售项目的关系

两个项目共享 JD 原文与来源清单，但研究问题不同：
- `retail-agent-eval`：轨迹评分是否可信、可定位反馈能否改善 Agent；
- `foundation-model-eval`：基座能力怎样可靠测量、错误诊断能否指导等预算 SFT 选样。

两边不共享运行结果、模型权重或“已验证”声明；相同的是实验纪律、来源记录和证据边界。
