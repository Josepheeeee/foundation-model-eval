# 复现、改进与证据边界

## 项目定位

这是面向基座模型评测与训练数据选择的研究型工程项目：把“测量什么、怎么测、错在哪、怎样在等预算下选数据、训练后如何独立验证”接成可追溯闭环。它使用公开基座和公开 benchmark，自行训练 LoRA，但不是预训练研究，也不是新的 benchmark 论文。

## 归属清单

| 内容 | 归属 | 本项目工作 |
|---|---|---|
| GSM8K/SVAMP 数据与原始任务 | 原作者/公开数据集 | 固定 revision、划分、样本级记录与评分适配 |
| MMLU-Pro/BBH/IFEval/HumanEval+ | 上游 benchmark | 接入原生指标、提取规则、受限执行；不改题目 |
| lm-evaluation-harness | EleutherAI | 参考实现与逐样本核对；不重复造通用评测框架 |
| LlamaFactory | hiyouga | LoRA SFT 执行；本项目只生成数据、配置、来源和接回流程 |
| EvalPlus | EvalPlus 团队 | HumanEval+ 功能测试与受限容器执行 |
| RULER | NVIDIA | 长上下文任务定义参考；本地固定长度诊断生成器 |
| 固定 dev 留出、长度分层、错误加权、等 Token 预算、配对分析 | 本项目实现 | 可复现的 B1/B2 选择与报告 |
| 数据选择方法本身 | 已有研究主题 | 不声称首次提出“难例优先/错误驱动选样” |

## 个人改进：等预算的基座错误诊断选样

把选样写成一个受控对照：

1. 在 GSM8K 官方 train 上固定 SHA-256 留出 500 dev，其余 6973 为训练池；
2. 用同一基座、同一 completion 协议诊断训练池，得到每个样本的答对/答错；
3. B1 在长度层内随机选 2,048 条；B2 在**同一层内**把答错权重设为 3；
4. 通过同层交换把两组有效训练 Token 压到 1% 以内；
5. 用同一 LoRA 配置、三个种子训练；
6. 在冻结的 GSM8K test 上做样本级配对比较，SVAMP 只做迁移，其他任务检查退化。

这不是“多训练”或“换更大模型”。两组的样本数、长度分布、Token 预算、训练超参和种子都匹配；差异只在选样权重。若 B2−B1 的 CI 跨 0，结论就是没有稳定证据，不把负结果改写成正结果。

## 哪些结果可以支持主张

- 三种子、完整 test、同一协议下 B2−B1 的 GSM8K 差值方向一致且 95%CI 不跨 0；
- SVAMP 迁移不出现明显退化，辅助任务没有系统性下降；
- 选样记录、诊断、训练日志、权重 hash 和评测 run 可逐项复查；
- 失败案例能说明 B2 在哪些题型/长度上仍失败，而不是只展示平均分。

## 哪些结果不足以支持主张

- 只跑一个种子、只报告最好种子、用 test 调选样或超参；
- 两组 Token/长度不匹配，或 B1 不是同池随机；
- 只比较 B2 与 B0，缺少 B1 这个“等预算随机”对照；
- 用 LLM Judge 替代确定性答案，或把 unsupported/执行失败算作 pass；
- 只在一个模型/数据 revision 上有效，却写成普遍规律；
- 把 LoRA SFT 说成预训练，或把本地 RULER 诊断说成官方榜单。

## 面试时可讲述的链路

“我发现基座在 GSM8K 训练池上的错误并不是均匀分布。为了区分‘多给数据’与‘给对数据’，我在固定 500 dev 后，把 6973 条训练池按长度分层，构造等样本、等 Token 的 B1 随机组和 B2 错误加权组，用同一 LoRA/种子训练，在冻结 test 上做配对 Bootstrap，并用 SVAMP 检查迁移、其他 benchmark 检查退化。结果无论正负，我都保留选样、训练和评测的全部哈希与失败案例。”

只有真实实验完成后才填写具体差值、CI 和成本；当前文档不预填收益。
